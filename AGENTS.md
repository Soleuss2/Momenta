# AGENTS.md — Momenta

Guidelines for AI coding agents working on this repository. Read this before making changes.

## What this project is

Momenta is a private shared journal and memory-keeping web app built for two people. It runs as a PWA (installable, offline-capable) and is deployed on Vercel.

## Stack

| Layer | Technology |
|---|---|
| Framework | Next.js 16.3.2 (App Router + Turbopack) |
| UI | React 19, Tailwind CSS v4, Framer Motion, Lucide React |
| Language | TypeScript 5 (strict) |
| Auth & Data | Supabase (`@supabase/ssr`, `@supabase/supabase-js`) |
| PWA | Serwist (`@serwist/next`, `@serwist/cli`) |
| Package manager | pnpm |
| Hosting | Vercel |

**Use pnpm only.** Never suggest `npm install`, `yarn add`, or `npx` when a pnpm equivalent exists.

Non-negotiable rules
1. Supabase client creation
tsx
// Browser components
import { createClient } from "@/lib/supabase/client";

// Server components / route handlers
import { createClient } from "@/lib/supabase/server";
Never call createClient() at the top level of a client component. It runs during prerender and fails on Vercel if env vars aren't present at build time. Call it inside event handlers, useEffect, or after a session check.

2. useSearchParams requires <Suspense>
Any client component that reads query params must be wrapped:

tsx
"use client";
import { Suspense } from "react";
import { useSearchParams } from "next/navigation";

function Inner() {
  const params = useSearchParams();
  return <div>{params.get("q")}</div>;
}

export default function Page() {
  return (
    <Suspense fallback={null}>
      <Inner />
    </Suspense>
  );
}
Without this, next build fails on the route with "Error occurred prerendering page."

3. Protected routes need two guards
middleware.ts refreshes the Supabase session and redirects unauthenticated users away from /users/*.

The page itself must also guard with a useEffect checking supabase.auth.getUser() and redirecting if no session.

Never rely on one alone. Middleware is the security boundary; the client guard handles session expiry and sign-out in other tabs.

4. "use client" only when needed
Add it only if the file uses hooks, browser APIs, event handlers, Framer Motion, or the Supabase browser client. Server components are the default.

5. PWA file tracking
File	Commit?	Reason
serwist.config.js	✅	Source config
src/app/sw.ts	✅	Source service worker
src/app/manifest.ts	✅	Source manifest
src/app/layout.tsx	✅	Metadata + viewport
public/sw.js	❌	Generated by Serwist
public/workbox-*.js	❌	Generated by Serwist
After editing sw.ts or serwist.config.js, test locally with pnpm build && pnpm start. Serwist is disabled in pnpm dev.

6. Icons and images
SVGs go in public/ and use a plain <img> tag (e.g., /momenta_logo.svg). next/image isn't needed for SVGs.

Raster images use <Image> from next/image with explicit width and height.

Never shadow the browser's Image global without importing next/image first.

7. TypeScript
Strict mode. No any, no @ts-ignore. Use unknown and narrow.

Prefer type over interface unless extending.

Every exported function and component prop gets an explicit type.

8. Styling
Tailwind utilities only. Custom tokens live in src/app/globals.css.

Rose/pink theme. Dark mode toggles .is-night on the root <main>.

Mobile-first: default styles for small screens, then sm:, md:, lg:.

Safe area insets: env(safe-area-inset-top) and env(safe-area-inset-bottom).

Touch targets ≥ 44px.

Semantic HTML: <button> not <div onClick>.

9. Git workflow
Never commit directly to master.

Branch names: feature/short-description, fix/short-description.

Commit messages: imperative mood ("Add auth guard", not "Added" or "Adding").

Push branch → Vercel preview → merge to master.

Never commit: .env, public/sw.js, public/workbox-*, node_modules/, .next/, package-lock.json.

Common tasks
Add a protected page under /users
Create src/app/users/<name>/page.tsx.

Add "use client" if it needs interactivity.

Copy the auth guard pattern from src/app/users/page.tsx.

Confirm the middleware matcher covers it (current matcher handles all of /users/*).

Test: sign out → visit the route → confirm redirect.

Add a Supabase table
Create it in the Supabase dashboard.

Enable Row Level Security.

Add a policy scoped to auth.uid() = user_id.

Add the TypeScript type in src/lib/supabase/types.ts.

Never disable RLS in production.

Test PWA features
pnpm build && pnpm start

Open Chrome DevTools → Application → Service Workers.

Confirm sw.js is activated.

Test offline via DevTools → Network → Offline.

Debugging checklist
Build works locally but fails on Vercel:

Are both NEXT_PUBLIC_SUPABASE_* variables set in Vercel for all environments?

Does any client component call createClient() at top level?

Is useSearchParams wrapped in <Suspense>?

Is there a window / document reference in a server component?

Auth fails with "Invalid login credentials":

Does the user exist in Supabase → Authentication → Users?

Is email_confirmed_at set?

Does a matching row exist in auth.identities?

Are the env vars pointing at the correct Supabase project?

PWA install prompt doesn't appear:

Is the site on HTTPS (or localhost)?

Does /manifest.webmanifest return valid JSON?

Are the icons 192×192 and 512×512 PNG?

Is sw.js activated in DevTools → Application → Service Workers?

Did the user interact with the page for ~30 seconds?

What NOT to do
❌ Don't install next-pwa or next-pwa-turbo — broken with Next.js 16 + Turbopack.

❌ Don't call Supabase admin APIs (service_role) from client components.

❌ Don't disable middleware.ts auth checks "temporarily."

❌ Don't commit generated service worker files.

❌ Don't push directly to master.

❌ Don't use window.location.href for in-app navigation — use router.push() from next/navigation.

❌ Don't hardcode Supabase URLs or keys — read from process.env.

❌ Don't add "use client" to the root layout.

Escalate to the user when
A fix requires installing new dependencies.

A change affects the Supabase schema or RLS policies.

A decision could impact security (auth flow, secret exposure, RLS).

You're about to delete files or reorganize directories.

A change might break the PWA or the Vercel deployment.

Response format
Be concise. No preamble.

Show code first, explain after.

Quote the actual error when debugging.

Reference files with paths and line numbers (src/app/users/page.tsx:42).

Ask when uncertain — don't guess at project conventions.
